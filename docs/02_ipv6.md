# 3.5 – TCP i UDP po IPv6

## Co jest realizowane

Te same programy co w [01_tcp_udp.md](01_tcp_udp.md), działające po IPv6:

| Program | IPv6 |
|---|---|
| `tcp_server -6`, `udp_server -6` | nasłuch na `[::]:port`, z `IPV6_V6ONLY = 1` |
| `tcp_client`, `udp_client` | domyślnie `AF_UNSPEC` – rodzinę wybiera adres w `-h`; `-4`/`-6` wymusza |

Adresy kontenerów:

| Rola | IPv4 | IPv6 (ULA) |
|---|---|---|
| `net-server` | `192.168.1.201` | `fd00:10::201` |
| `net-client` | `192.168.1.202` | `fd00:10::202` |

`fd00::/8` to adresy **ULA** (Unique Local Address, RFC 4193) – odpowiednik prywatnych
adresów IPv4 (192.168.x.x), nie są routowane w Internecie.

## Co trzeba było zmienić w kodzie

Bardzo mało – dzięki temu, że adresy od początku idą przez `getaddrinfo()`/`getnameinfo()`,
a struktury to `sockaddr_storage`:

| Miejsce | IPv4 | IPv6 |
|---|---|---|
| `hints.ai_family` w serwerze | `AF_INET` | `AF_INET6` (flaga `-6` przez `parse_family()`) |
| `hints.ai_family` w kliencie | – | `AF_UNSPEC` (obie rodziny) lub wymuszona `-4`/`-6` |
| adres „dowolny” z `AI_PASSIVE` | `0.0.0.0` | `::` |
| dodatkowa opcja serwera | – | `setsockopt(IPPROTO_IPV6, IPV6_V6ONLY, 1)` przed `bind()` |
| log adresu (`addr_to_str`) | `192.168.1.202:43122` | `[fd00:10::202]:43122` |

Reszta – `socket`, `bind`, `listen`, `accept`, `recv`, `send_all`, `recvfrom`, `sendto` –
jest identyczna. `getaddrinfo()` zwraca gotowe `sockaddr_in` albo `sockaddr_in6`,
a `ai_family`/`ai_addr`/`ai_addrlen` przekazujemy dalej bez zaglądania do środka.

Sekwencja wywołań serwera IPv6:

```
getaddrinfo(NULL, port, AF_INET6, AI_PASSIVE) → socket(AF_INET6) → setsockopt(SO_REUSEADDR)
→ setsockopt(IPV6_V6ONLY = 1) → bind([::]:port) → listen → accept ...   (TCP)
                                                → recvfrom/sendto ...   (UDP)
```

## `IPV6_V6ONLY`

Linux domyślnie (`sysctl net.ipv6.bindv6only = 0`) pozwala gniazdu IPv6 zbindowanemu na `::`
przyjmować **również IPv4**. Połączenie z `192.168.1.202` widać wtedy jako adres
**IPv4-mapped** `::ffff:192.168.1.202` (RFC 4291) – jedno gniazdo obsługuje obie wersje.

Ustawiamy `IPV6_V6ONLY = 1`, żeby podział był czysty:

- `tcp_server -4` obsługuje tylko IPv4, `tcp_server -6` tylko IPv6,
- oba mogą działać **jednocześnie na tym samym porcie** (bez V6ONLY drugi `bind` dostałby
  `Address already in use`, bo `[::]:5000` zajmowałby też `0.0.0.0:5000`),
- w logach zawsze widać prawdziwą wersję IP klienta.

Opcja musi być ustawiona **przed `bind()`**.

## Kolejność adresów przy `AF_UNSPEC`

Dla nazwy z kilkoma adresami `getaddrinfo()` sortuje wyniki wg RFC 6724 (`/etc/gai.conf`).
W domyślnej tablicy adresy ULA (`fc00::/7`) mają **niższy priorytet niż IPv4**, więc
dla nazwy z rekordami `192.168.1.201` i `fd00:10::201` pierwszy będzie zwykle IPv4.
`tcp_client` próbuje adresów po kolei, aż `connect()` się uda; `udp_client` bierze pierwszy.
Flaga `-6` wymusza IPv6.

## Demo na dwóch kontenerach

### Przygotowanie – czy IPv6 działa

```
net-server:  ip -6 addr show dev eth0     # inet6 fd00:10::201/64 scope global
net-client:  ip -6 addr show dev eth0     # inet6 fd00:10::202/64 scope global
net-client:  ping -6 -c 2 fd00:10::201
```

Jeśli brakuje adresu – ustaw statyczny IPv6 w konfiguracji sieci kontenera w Proxmoxie.

### TCP po IPv6

```
net-server (t1):  ./build/tcp_server -6
net-server (t2):  sudo tcpdump -i eth0 -n ip6 and tcp port 5000
net-client:       ./build/tcp_client -h fd00:10::201 -m "test6"
```

Oczekiwany wynik:

```
net-server:  [TCP][srv] nasłuchuję na [::]:5000 (Ctrl+C kończy)
             [TCP][srv] połączenie od [fd00:10::202]:43122
             [TCP][srv] 6 B od [fd00:10::202]:43122: "test6"

net-client:  [TCP][cli] połączono z [fd00:10::201]:5000
             [TCP][cli] odpowiedź (6 B): "test6"
```

```
net-server:  ss -tlnp | grep 5000         # [::]:5000
net-client:  nc -6 fd00:10::201 5000      # nc jako klient po IPv6
```

### UDP po IPv6

```
net-server (t1):  ./build/udp_server -6
net-server (t2):  sudo tcpdump -i eth0 -n ip6 and udp port 5001
net-client:       ./build/udp_client -h fd00:10::201 -m "test6"
net-client:       nc -u -6 fd00:10::201 5001
```

Na serwerze: `[UDP][srv] 6 B od [fd00:10::202]:5xxxx: "test6"`.

### Obie wersje naraz na jednym porcie (efekt `IPV6_V6ONLY`)

```
net-server:  ./build/tcp_server -4 &
net-server:  ./build/tcp_server -6 &
net-server:  ss -tlnp | grep 5000              # dwa gniazda: 0.0.0.0:5000 i [::]:5000

net-client:  ./build/tcp_client -h 192.168.1.201 -m v4   # obsługuje serwer -4
net-client:  ./build/tcp_client -h fd00:10::201 -m v6    # obsługuje serwer -6
```

Każdy serwer loguje tylko swoją wersję IP. Analogicznie `udp_server -4` i `udp_server -6`.

Gniazdo IPv6 nie przyjmuje IPv4 – zostaw tylko serwer `-6`:

```
net-server:  kill %1                                      # zatrzymuje tcp_server -4
net-client:  ./build/tcp_client -h 192.168.1.201 -m v4   # connect: Connection refused
```

### Wybór adresu przez klienta (opcjonalnie)

Dopisz na `net-client` do `/etc/hosts` (sudo) dwie linie z tą samą nazwą:

```
192.168.1.201  net-server
fd00:10::201   net-server
```

```
net-client:  getent ahosts net-server                     # kolejność z getaddrinfo
net-client:  ./build/tcp_client -h net-server -m auto     # zwykle łączy po IPv4 (wyższy priorytet niż ULA)
net-client:  ./build/tcp_client -6 -h net-server -m v6    # wymuszone IPv6
net-client:  ./build/tcp_client -4 -h net-server -m v4    # wymuszone IPv4
```
